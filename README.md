# Приложение для заметок — практические работы 13–18

Репозиторий содержит реализацию прогрессивного веб-приложения (PWA) для управления заметками с постепенным усложнением функциональности: от базового офлайн-доступа через Service Worker до системы напоминаний с WebSocket и Push-уведомлениями.

## Структура проекта

```
prakticheskaya_17_18/
├── notes-app/                  # PWA-приложение (задания 13–17)
│   ├── content/
│   │   ├── home.html           # Динамический контент главной страницы (App Shell)
│   │   └── about.html          # Страница «О приложении»
│   ├── icons/                  # Набор иконок разных размеров (16–512px)
│   ├── index.html              # Каркас приложения (App Shell)
│   ├── app.js                  # Основная логика клиента
│   ├── sw.js                   # Service Worker
│   ├── manifest.json           # Web App Manifest
│   ├── server.js               # Node.js сервер (Express + Socket.IO + web-push)
│   ├── package.json
│   ├── localhost+2.pem         # TLS-сертификат для локального HTTPS
│   └── localhost+2-key.pem     # Приватный ключ для локального HTTPS
└── package-lock.json
```

## Практическое задание 13 — Service Worker

Разработано базовое веб-приложение для управления заметками с поддержкой офлайн-режима через Service Worker. Данные хранятся в `localStorage`, а статические ресурсы кэшируются при первой загрузке.

**Технологии:** HTML, CSS, JavaScript, Service Worker API, localStorage

### Реализованный функционал

- Просмотр и добавление заметок.
- Сохранение данных в `localStorage`.
- Регистрация Service Worker и кэширование статических ресурсов (`index.html`, `app.js`).
- При отсутствии сети страница загружается из кэша, интерфейс остаётся полностью работоспособным.

### Жизненный цикл Service Worker

| Событие | Действие |
|---------|----------|
| `install` | Предварительное кэширование статических файлов |
| `activate` | Очистка устаревших кэшей |
| `fetch` | Возврат ресурса из кэша или из сети |

## Практическое задание 14 — Web App Manifest

Приложение дополнено файлом `manifest.json`, что позволяет устанавливать его на устройство как полноценное PWA.

**Технологии:** Web App Manifest, mkcert (локальный HTTPS)

### Реализованный функционал

- Создан `manifest.json` с полями: `name`, `short_name`, `start_url`, `display`, `background_color`, `theme_color`, `description`, `orientation`, `icons`.
- Подготовлен набор иконок в формате PNG размерами от 16×16 до 512×512, включая `apple-touch-icon`.
- Манифест подключён в `index.html` через `<link rel="manifest">`.
- Добавлены мета-теги для интеграции с мобильными платформами (Android и iOS).
- Service Worker обновлён: иконки и `manifest.json` добавлены в список кэшируемых ресурсов.

### Поля manifest.json

| Поле | Значение |
|------|----------|
| `name` | Мои заметки |
| `short_name` | Заметки |
| `display` | `standalone` |
| `theme_color` | `#4285f4` |

## Практическое задание 15 — HTTPS + App Shell

Настроено доверенное локальное HTTPS-соединение с помощью `mkcert`, а архитектура приложения переработана по паттерну App Shell.

**Технологии:** mkcert, Node.js HTTPS, App Shell архитектура

### Реализованный функционал

- Сгенерированы локальные TLS-сертификаты (`localhost+2.pem`, `localhost+2-key.pem`) через `mkcert`.
- Реализована архитектура App Shell: каркас приложения (шапка, навигация) хранится в `index.html` и кэшируется при первом посещении.
- Динамический контент вынесен в отдельные файлы: `content/home.html` и `content/about.html`.
- Добавлена страница «О приложении».
- Навигация между страницами реализована через `fetch` без перезагрузки.

### Стратегии кэширования

| Тип ресурса | Стратегия |
|-------------|-----------|
| Статика (App Shell) | Cache First |
| Динамический контент (`/content/*`) | Network First с фолбеком на кэш |

## Практическое задание 16 — WebSocket + Push

Добавлена двусторонняя связь в реальном времени через Socket.IO и поддержка push-уведомлений с использованием Web Push API.

**Технологии:** Node.js, Express, Socket.IO, web-push, VAPID

### Реализованный функционал

- Запущен Node.js-сервер (Express + Socket.IO + web-push) с поддержкой HTTPS.
- При добавлении заметки клиент отправляет событие `newTask` на сервер, сервер рассылает `taskAdded` всем подключённым клиентам.
- Все подключённые вкладки получают всплывающее сообщение о новой задаче в реальном времени.
- Реализована подписка на Push-уведомления через `PushManager`.
- В интерфейс добавлены кнопки «Включить уведомления» / «Отключить уведомления».
- Push-уведомления отправляются всем подписанным пользователям при добавлении новой заметки.

### API эндпоинты

| Метод | URL | Описание |
|-------|-----|----------|
| `POST` | `/subscribe` | Сохранение push-подписки |
| `POST` | `/unsubscribe` | Удаление push-подписки |

### WebSocket события

| Событие | Направление | Описание |
|---------|------------|----------|
| `newTask` | Клиент → Сервер | Новая заметка добавлена |
| `taskAdded` | Сервер → Все клиенты | Уведомление о новой заметке |

## Практическое задание 17 — Детализация Push (напоминания)

Реализована система напоминаний с возможностью откладывания. Напоминания планируются на сервере с помощью `setTimeout` и работают даже при закрытом приложении.

**Технологии:** Node.js, setTimeout, PushManager, Notification Actions API

### Реализованный функционал

- В форму добавлено поле `datetime-local` для указания времени напоминания.
- Структура заметок в `localStorage` расширена: добавлены уникальный `id` и поле `reminder` (timestamp).
- При создании заметки с напоминанием клиент отправляет событие `newReminder` на сервер.
- Сервер планирует отправку push-уведомления через `setTimeout` и хранит активные таймеры в `Map`.
- В push-уведомлении с напоминанием отображается кнопка «Отложить на 1 минуту».
- Service Worker обрабатывает нажатие кнопки и отправляет `POST /snooze` на сервер.
- Сервер отменяет старый таймер и устанавливает новый через 1 минуту.

### API эндпоинты (обновлённые)

| Метод | URL | Описание |
|-------|-----|----------|
| `POST` | `/subscribe` | Сохранение push-подписки |
| `POST` | `/unsubscribe` | Удаление push-подписки |
| `POST` | `/snooze?reminderId={id}` | Откладывание напоминания на 1 минуту |

### WebSocket события (обновлённые)

| Событие | Направление | Описание |
|---------|------------|----------|
| `newTask` | Клиент → Сервер | Обычная заметка добавлена |
| `taskAdded` | Сервер → Все клиенты | Уведомление о новой заметке |
| `newReminder` | Клиент → Сервер | Заметка с напоминанием добавлена |

## Запуск проекта

```bash
cd prakticheskaya_17_18/notes-app
npm install
node server.js
```

Откройте в браузере: `https://localhost:3001`

> При наличии сертификатов `localhost+2.pem` и `localhost+2-key.pem` сервер запустится по HTTPS. В противном случае автоматически запустится HTTP-сервер.

### Генерация собственных HTTPS-сертификатов (опционально)

```bash
# Установка mkcert
# Windows:  choco install mkcert
# macOS:    brew install mkcert
# Linux:    см. документацию mkcert

mkcert -install
mkcert localhost 127.0.0.1 ::1
```

### Зависимости

| Пакет | Назначение |
|-------|-----------|
| `express` | HTTP/HTTPS-сервер и раздача статики |
| `socket.io` | WebSocket (двусторонняя связь в реальном времени) |
| `web-push` | Отправка push-уведомлений (VAPID) |
| `body-parser` | Парсинг JSON в теле запросов |
| `cors` | Разрешение кросс-доменных запросов |
